# v0.3.0 Fixed Specification: WAV Analyzer CLI and JSON Report

Status: **Locked for implementation**  
Tracking issue: #4  
Base release: v0.2.0  
Base commit: `cf15028852516db237e2e643616eec971c06d668`

## 1. Purpose

v0.3.0 adds an offline WAV analysis executable around the existing real-time-safe diagnostics core.

The executable reads a supported WAV file in bounded blocks, converts samples to `double`, processes them with `Analyzer<double>`, and emits a deterministic UTF-8 JSON report.

The core library remains independent of file I/O, command-line parsing, JSON, networking, and third-party production dependencies.

## 2. Build contract

Add:

- Executable target: `lsw_audio_diagnostics_cli`
- CMake option: `LSW_AUDIO_DIAG_BUILD_CLI`, default `ON`
- C++ standard: C++17
- Link dependency: `LSW::AudioDiagnostics`

The CLI and any offline helper target must remain outside the real-time `Analyzer` processing path.

## 3. Command contract

```text
lsw_audio_diagnostics_cli analyze <input.wav> [--output <report.json>] [--pretty] [--block-size <frames>]
lsw_audio_diagnostics_cli --help
lsw_audio_diagnostics_cli --version
```

Rules:

- Default block size: `4096` frames
- Valid block-size range: `1..1048576`
- Without `--output`, JSON is written to stdout
- With `--output`, JSON is written to the requested file and stdout remains empty on success
- Human-readable diagnostics and errors are written to stderr
- `--pretty` changes whitespace only
- Unknown options are errors
- Duplicate singleton options are errors
- Missing option values are errors
- Extra positional arguments are errors

## 4. Exit codes

| Code | Meaning |
|---:|---|
| 0 | Success |
| 2 | Command-line usage or argument error |
| 3 | Input open or read error |
| 4 | Malformed or unsupported WAV |
| 5 | Analyzer preparation or internal analysis error |
| 6 | Output create, write, or finalize error |

## 5. Supported WAV input

Supported:

- Little-endian `RIFF/WAVE`
- Exactly one `fmt ` chunk
- Exactly one `data` chunk
- Unknown chunks skipped correctly, including odd-byte padding
- Mono or stereo
- PCM integer 8, 16, 24, or 32 bit
- IEEE float 32 or 64 bit
- `WAVE_FORMAT_EXTENSIBLE` with PCM or IEEE-float subtype
- Streaming decode without complete-file audio buffering
- Processing of the final partial block

Rejected as exit code `4`:

- RF64
- RIFX
- Compressed codecs
- Zero channels or more than two channels
- Missing or duplicate required chunks
- Invalid sample rate, byte rate, block align, bit depth, valid-bit metadata, or chunk size
- Truncated headers or audio payload
- Data size not divisible by block align
- Integer overflow or file-offset overflow

## 6. Sample conversion

- Analysis type: `Analyzer<double>`
- PCM 8-bit is unsigned and normalized around zero
- PCM 16/24/32-bit is signed little-endian and divided by the positive full-scale power of two
- IEEE float samples are converted to `double` without clipping
- NaN and infinity remain available to existing diagnostics
- Interleaved WAV frames are deinterleaved into fixed-size per-channel buffers

## 7. Analyzer configuration

Set only:

- `sampleRate` from the WAV header
- `maximumBlockSize` from the CLI option or default
- `numberOfChannels` from the WAV header

All remaining `AnalyzerConfig` values use the v0.3.0 library defaults.

## 8. JSON contract

Requirements:

- UTF-8 JSON
- Deterministic field order
- Locale-independent number formatting
- `schemaVersion` is integer `1`
- No timestamp, host name, absolute-path expansion, random identifier, or other nondeterministic field
- Preserve the input path exactly as supplied by the user
- Serialize finite values as JSON numbers
- Serialize any unexpected non-finite report metric as `null`
- Never emit invalid JSON tokens such as `NaN` or `Infinity`

Top-level structure:

```json
{
  "schemaVersion": 1,
  "tool": {
    "name": "lsw_audio_diagnostics_cli",
    "version": "0.3.0"
  },
  "input": {
    "path": "input.wav",
    "fileSizeBytes": 0
  },
  "audio": {
    "container": "RIFF/WAVE",
    "encoding": "pcm_s16",
    "sampleRate": 48000,
    "channelCount": 2,
    "bitsPerSample": 16,
    "validBitsPerSample": 16,
    "frameCount": 0,
    "durationSeconds": 0.0
  },
  "analysis": {
    "processedFrameCount": 0,
    "processedBlockCount": 0,
    "diagnosticFlags": [],
    "channels": [],
    "stereo": {},
    "channelEvents": [],
    "stereoEvents": {}
  }
}
```

Detailed mapping:

- `processedFrameCount` maps to `Snapshot::processedSampleCount`
- `processedBlockCount` maps to `Snapshot::processedBlockCount`
- `diagnosticFlags` is a stable lowercase snake-case name array in enum-bit order
- `channels` contains exactly one item per active input channel
- Channel fields mirror `ChannelMetrics` using lower camel case
- Stereo fields mirror `StereoMetrics` using lower camel case
- Event fields mirror `EventState`, `ChannelEvents`, and `StereoEvents` using lower camel case
- Mono reports retain the neutral core values in `stereo` and `stereoEvents`

## 9. Output-file behavior

- Complete WAV parsing and analysis before opening or truncating the requested output path
- Reject input and output resolving to the same file before truncation
- Existing output files may be replaced after successful analysis
- On output failure, return exit code `6`
- Make a best effort to remove a newly created incomplete output file

## 10. Implementation boundaries

Expected separation:

```text
apps/cli/main.cpp
src/offline/wav_reader.cpp
src/offline/json_report_writer.cpp
include/lsw/audio_diag/offline/wav_reader.hpp
include/lsw/audio_diag/offline/json_report_writer.hpp
tests/cli_argument_tests.cpp
tests/wav_reader_tests.cpp
tests/json_report_tests.cpp
```

Equivalent filenames are acceptable only when the same architectural boundary is retained.

Offline helpers may use a dedicated non-real-time support target. They must not add file or JSON responsibility to `Analyzer`.

At minimum:

- Help and version
- Missing argument

- Duplicate argument
- Invalid block size
- PCM 8/16/24/32 mono and stereo
- IEEE float 32/64 mono and stereo
- Extensible PCM and float
- Unknown-chunk skipping

- Final partial block
- Float NaN and infinity preservation into diagnostics
- Truncated RIFF, `fmt `, and `data`
- Missing and duplicate `fmt ` or `data`
- Invalid metadata
- Unsupported format and channel count
- Data-size alignment failure
- Compact JSON golden test
- Pretty JSON golden test
- Input-path JSON escaping
- Output create and replace
- Same-input/output rejection
- End-to-end exit-code behavior

Tests must not depend on the network, current time, current locale, machine-specific absolute paths, or downloaded fixtures.

Prefer programmatically generated binary WAV fixtures.

## 14. Out of scope

- Rules, presets, pass/fail quality gates, SARIF, JUnit, or GitHub annotations
- True Peak
- LUFS, LRA, or PLR
- Event timeline ranges
- RF64, AIFF, FLAC, MP3, or multichannel files
- Downmixing
- Recursive directory scanning, globbing, watch mode, or stdin audio streaming
- GUI, JUCE, VST3, or audio-device capture
- Public API freeze or ABI guarantee

## 16. Failure conditions

- Direct push to `main`
- Force push
- Required-check failure
- Secret, token, credential, or private machine path committed or printed
- Silent incorrect decoding of unsupported WAV input
- Nondeterministic JSON for identical input and options
- Complete-file audio buffering in the final implementation
- New production third-party dependency without a separate scope decision
